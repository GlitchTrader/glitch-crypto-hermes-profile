# Hermes profile delivery methodology

This profile uses the same method as the gateway: Wayfinder for consequential
decision fog, `to-spec`, GitHub Spec Kit `spec.md` -> `plan.md` -> `tasks.md`,
Architectonic ontology, and one Architectonic Rail ledger.

## Authority and lifecycle

1. Read the constitution, authority, ontology, paired gateway contract, Rail item, source, and active spec.
2. Grill only unresolved contract questions; cite gateway truth instead of asking again.
3. Use Wayfinder only when multiple consequential profile decisions remain.
4. Specify independently testable behavior without credentials, direct venue tools, quantity ownership, or hidden deterministic strategy.
5. Plan the smallest event-driven, idempotent, preemptible worker or command slice.
6. Treat `tasks.md` as decomposition inside one Rail item; `operations/ledger.json` alone owns status.
7. Implement directly on `main`; regenerate `SHA256SUMS`, verify the distribution, run all tests, update Rail evidence, and then push.
8. Update GitHub issues to source truth. Open no PR unless the human asks.

Keep implemented, packaged, installed, activated, shadow-observed,
production-accepted, and empirically profitable as separate states.
