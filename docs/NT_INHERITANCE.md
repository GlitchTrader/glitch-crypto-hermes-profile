# NT inheritance, not NT assumptions

The 2026-09-09 Crypto paper activation carries engineering/trading principles
from the NT line. It does not transfer NT fills, performance, learned statistics,
account policy, replication, UI, cron, schedules, or installed state.

- Current positions/receipts outrank previous HOLD/EXIT narratives.
- Exact staged UUID/body survives a lost response; no new model call for recovery.
- Protection works independently of the LLM. This run uses simulated marks and
  protection, not a native exchange bracket or realistic liquidity simulation.
- Larger auction structure supplies objective/invalidation; microstructure helps
  timing. Cheap risk comes from location, not squeezing a stop into noise.
- Confirmation/retests are evidence, not mandatory sequential gates; waiting has
  an opportunity cost. No activity quota or forced entry.
- A loss alone is not invalidation; name changed evidence for discretionary exit.
  After progress, compare continuation with giveback, not only original stop.
- Experimental scores are not calibrated probabilities. Keep costs and uncertainty
  explicit; no made-up success rate or copied NT edge.
- Keep prospective packets/decisions/receipts. The learner remains proposal-only
  infrastructure, not a claimed self-improvement loop.
- Separate CryptoGlitch profile/data/processes. NT remains untouched.
- Installed distribution verification checks exact payload bytes and the semantic
  manifest (version, requirements, description, author, owned paths). Hermes owns
  manifest name/source/install timestamp metadata and YAML serialization; those
  installation details are reported separately, not mistaken for payload drift.
- Freeze this paper version for observation; later changes need a causal reason,
  bounded diff and tests. Zero trades and losses prompt investigation, not forced
  signals or blind parameter changes.

The Windows process probe uses query-only process APIs, not `os.kill(pid, 0)`;
see [Python's Windows kill contract](https://docs.python.org/3/library/os.html#os.kill).
Completed context comes from [Binance public klines](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/market-data/rest-api/Kline-Candlestick-Data).
